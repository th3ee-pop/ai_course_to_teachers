# 生态岛行动

适合小学高年级与中学的 3D 小组探究工具。每组共用一台电脑，成员轮换观察员、操作员、记录员。两种情境：旱季挑战、鹿群过多。

## 课堂启动

1. 解压完整文件夹。电脑需要 Python 3、支持 WebGL 的现代浏览器。
2. macOS 双击 `启动.command`；Windows 双击 `启动-Windows.bat`。也可在本文件夹运行 `python3 scripts/serve.py`。
3. 浏览器打开终端显示的本地地址（优先 `http://127.0.0.1:8780/`）。保留终端窗口，结束时按 Ctrl+C。

全部模型、字体与程序随包提供。启动后无需互联网，不需要摄像头、账号或付费服务。请勿直接双击 dist/index.html，模型加载需要本地 HTTP 服务。Mac 如果禁止双击脚本，可在终端运行 `bash 启动.command`。

## 一节课的最小活动（25–35 分钟）

- 3 分钟：三人认领 A/B/C，选择情境。四人组可两人共同观察。
- 5 分钟：播放原岛 24 轮，至少记录一条带轮次的发现。每轮是模型时间，不是真实一天。
- 5 分钟：先写“我们预测……因为……”，讨论改变一个条件，使用 6 点预算布置，最多 3 项行动。
- 5 分钟：轮换角色，以相同起点、实验编号、天气再次运行，记录关键变化。
- 7 分钟：比较原岛与方案，回看具体轮次，写解释并导出报告。组间讨论不同方案的取舍。

小学侧重谁吃谁、数量变化及口头预测；中学增加自变量、控制条件、数量曲线与模型局限提示。随时可在手册底部切换学段。没有按动物数量排名的“最高分”。

## 场景操作

拖动旋转、滚轮缩放、右键平移。“近地观察”切换视角。点击动物或草地查看信息。布置阶段选工具后点击草地；也可展开“按地块编号布置”。水源覆盖邻近地块，补种恢复当前草量；投放鹿增加 6 只，投放狼增加 2 只。已布置的同一地块同种草地/水源措施不能重复扣费。运行中禁止追加干预。

## 公平对照与模型边界

程序采用离散地块、个体能量、觅食、捕食、草地再生与繁殖规则。确定性的随机函数由实验编号、轮次、动物标识及事件类型决定。两次使用相同初始世界和天气，方案仅在第二次第 0 轮应用。相同方案可复现；干预会改变后续个体与事件，不能声称所有事件逐个相同。

默认编号 731。旱季情境从 24 只鹿、5 只狼开始，第 9–16 轮草地再生显著减慢；鹿群过多从 46 只鹿、3 只狼开始。两种情境第 20 轮进入雨季。草地以 0–100% 表示；单个模型动物对应一只个体，最多 100 只。

水源仅提高附近草地的再生，本模型不直接模拟动物饮水、疾病、迁入迁出、完整食物网或真实地理环境。动物能量耗尽会死亡，不是“离岛”。模型参数用于课堂探索，未经实地生态数据校准；24 轮结果不代表长期稳定，不能作为真实野生动物管理建议。改变多个条件只能评价整套方案，无法将结果归因于其中一个因素。

模型思路可参考 [NetLogo Wolf Sheep Predation](https://ccl.northwestern.edu/netlogo/models/WolfSheepPredation)，本项目为独立实现，未复制其源代码。

## 保存、报告与组间交流

当前进度自动保存在该浏览器、该本地地址。刷新后暂停继续；不同端口视为不同存储空间。请在手册“证据与报告”中备份 JSON 进度，换机器时导入。学生输入仅保存在本机。

完成两次运行后可导出包含预测、行动位置、记录、解释与 25 个时点对照数据的 HTML 报告，浏览器可打印为 PDF。再次尝试方案前，建议先导出该次报告。之前的观察记录保留；方案记录带有干预名称与地块，避免与新方案混淆。

这是共用一台电脑的版本，没有跨设备实时联机。组间可交换报告文件。

## 开发与验证

Node.js 22.18+（已在 Node 24 验证）：`npm install`，`npm run dev -- --port 8780`。
`npm test` 检查可重复性、边界、动物投放、方案约束、保存格式和报告转义；`npm run build` 执行类型检查并生成离线程序。浏览器验收记录见 `tests/验收记录.md`。
