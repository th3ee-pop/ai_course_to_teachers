## 二、发现的问题与处理（已改入样章）

1. **“智能体”不是产品术语。** 承担角色卡的功能官方称**专家**（人设＋方法论＋工具链），在“我的专家”自建。全站无“智能体”概念。→ 样章三处已改为“专家”，并在首次出现处加一句术语解释。
2. **“工作空间”被当成“项目”使用。** 官方口径：工作空间＝任务的本地读写目录；**项目**才是带资产库(RAG)、指令、专家、技能的容器；轻应用的CSV须存在资产库（在线）页面才能持续读取。→ 样章全文十余处“工作空间／项目空间”统一改为“项目”“项目资产库”，并在板块B补一句CSV须在资产库的前提。
3. **口述札记的隐私表述过头。** 微信助理文档原文“语音消息：发送语音指令（需微信语音转文字功能）”——走微信语音，转写由微信完成，Local Whisper插不进去，且语音本身经微信通道。→ 改为“录音文件发给电脑端、由Local Whisper本地转写”，删去“信息不出这台机器”，改为“转写与整理都在本机完成，不经过任何在线转写接口”。
4. **“电脑须在触发时刻开机”是推断而非官方原文。** 自动化页与实践五均无此句；可佐证的是“配置保存在本地客户端”与微信助理页“电脑休眠、断网或关闭WorkBuddy，远程访问将暂时中断”。→ 改为“配置保存在本地客户端，也在本机运行——电脑休眠、断网或关掉客户端，当次触发就不会发生”。
5. **推送渠道是WorkBuddy小程序，不是泛指的手机。** → 提示词与生成结果要点两处已写明。
6. **未成年人条款（最重要的落地约束）。** 用户协议第十条：“本服务主要面向成年人提供。若您是未满18周岁的未成年人，您应在监护人监护、指导并获得监护人同意的情况下……方可使用本服务。”→ 样章把“机房各组轮流上机”改为“各组到教师机前轮流提问、教师在旁”，明确学生不注册不使用个人账号；家长告知书交付物增加“含学生在校使用AI学伴的告知与同意栏”。
7. **附图编号与出现顺序不符**（对话图原为附图-4却先出现）。→ 附图-3＝“护眼小卫士”对话，附图-4＝护眼行动看板；编写说明的作者实测清单与15号交接笔记已同步。

## 三、Web端实地点查另得的两条事实

- **项目详情页结构**：动态／计划／任务／资产四个标签，右侧“项目配置”含指令、连接器、专家、技能、自动化五项；任务输入框提示“@ 引用资产文件、项目待办或调用技能”。样章“项目＋资产库＋项目内自动化”的路径在Web端完整成立。
- **Web端未见“我的专家／创建专家”入口**（侧栏“更多”下只有“灵感”）。自建专家应在客户端完成。文档未提示这一差异，与“Web端与客户端个人Skill库互不相通”同属双端差异。**教师若要自建学伴角色，需安装客户端**——写作时不宜只说“在WorkBuddy里建一个专家”。

## 三点五、客户端实测：自建“护眼小卫士”专家（2026-08-16 22:07–22:14 实做）

在 WorkBuddy 客户端 v5.3.13 完整跑通了样章实测③，结论如下。

- **自建专家是对话式的，不是填表单。** 点“我的专家 → 创建专家”后跳到新建任务，自动挂上 `expert-manager` 技能并预填模板“帮我创建一个 XXX 专家，擅长 XXXXX”。把样章的角色卡文字发过去即可。样章原写的“生成一段可粘贴进配置项的角色设定文本”不符实际，已改。
- **创建流程五步**：初始化专家目录结构 → 填写 plugin.json 和 Agent MD → 生成专家头像（自动压到 512×512、≤500KB）→ 校验专家包 → 注册专家到市场。全程约 4 分钟。
- **“注册到市场”不是公开发布。** 专家包落在本机 `~/.workbuddy/plugins/marketplaces/my-experts/plugins/eye-care-guardian/`，与官方市场目录并列，属个人库。教师自建的学伴不会外泄，这一点可以放心写。
- **产物结构**：`agents/<name>.md`（YAML frontmatter 含 name/description/displayName/profession/maxTurns，正文为“核心能力／工作流程／输出规范”三段）＋ `avatars/expert.png` ＋ README.md。角色卡的四条约束被逐条落进工作流程与输出规范，保真度高。
- **但仍需教师核对**：生成的角色说明在讲“护眼工具制作”时，自行补了“简易视力表、用眼时间沙漏”作例子，与本项目的坐姿矫正支架、护眼提醒卡不符——AI 不知道本班任务卡。这个真实偏差已写进样章的生成结果要点，作为“教师必须通读修正”的实证。
- **边界测试通过**：问“晚上躲被窝里看书对眼睛有什么影响？”，答语适龄、有比喻、给出“三个一”建议（13秒）；问“帮我写一篇关于恐龙的作文”，答“这个我不知道。”并引导回项目范围（5秒）。附图-3 素材可由这两轮对话截取。
- **成本实测（对教师落地很关键）**：发任务前界面给出积分预估区间（本次显示“预计消耗 ◇5.1 ~ 112.5”）；创建专家实耗 **◇62.51**（一次性），之后每轮学伴问答仅 **◇1.07**（Auto 调度到 Deepseek-V4-Flash）。体验版每月 500 积分足以支撑“建一次专家＋整学期问答”。相较之下，一次课标 PDF 检索类任务耗 ◇33.52。

## 三点六、客户端实测：数据可视化与看板发布（2026-08-16 22:20–22:50 实做）

用 `书稿/附录/示例数据_护眼案例.csv`（385行）在客户端跑通了实测①②。

### 实测①：班级数据可视化（耗时 3分53秒）
- 新建“科学护眼项目”并填了项目指令（匿名边界＋读者适龄），挂上“护眼学伴”专家。
- **项目指令确实生效**：生成图表过程中 AI 自行修正“第三面板的刻度标签（1.75/5.25 不适合小学生阅读）”——这是项目指令里“读者为五年级学生、用词须适龄”起了作用，可作为“项目指令值得认真写”的实证。
- 输出的柱形图带全班平均 40% 参考线、超均值组标橙色，数据只到小组层面，符合匿名要求。可作附图-2 素材。
- **分析结论与样章完全对得上**：全班检出率 40.0%、户外均值 62 分钟（样章 61.9）、连续用眼 4.8→3.0、睡前电子产品 3.2→3.2 未改善。AI 独立从原始 CSV 复算出了“睡前用眼未改善”这个关键发现，说明样章的示例数据与结论自洽。
- 它还主动指出各组短板不同（G1 睡前屏幕最多且检出率最高，G6 连续用眼最频繁，G5 三项都较好可作经验分享组），比样章预设的结论更细。

### 实测②：看板生成与发布（耗时约 8 分钟，实耗 ◇61.27）
- **CSV 用中文文件名会给 Agent 添麻烦**：从资产库下载时它连试三次，报“URL 里的中文文件名编码被我抄错了一处”，改用正确编码才成功。给教师的建议是资产库文件用英文或数字命名。
- **看板实现是 `fetch("data.csv?t="+Date.now(), {cache:"no-store"})`**，读的是与 index.html **同目录**的 data.csv，不是项目资产库里的那份。所以“每周只更新 CSV 页面就自动变”需要修正为：**换 CSV 后要连页面一起重新发布，链接不变**。样章相应段落已改。
- **本地 file:// 打开时 fetch 被浏览器拦下**，页面回退到内置快照，页脚如实标注“内置数据快照（在线打开本页可自动读取最新 CSV）”；在线打开时页脚变为“实时读取 data.csv”。我实测改了本地 CSV 六行数据，本地页面不变（走快照）、线上页面标签为实时读取——两种状态都得到确认。这个“如实标注数据来源”的设计值得在书里点一句。
- **发布走的不是轻量发布，是 EdgeOne Pages**：Agent 自主部署，返回形如 `https://xxx.edgeone.cool?eo_token=...&eo_time=...` 的链接，**带 token 才能访问**，比 workbuddy.link 的“凭链接即可访问”多一层。这与 14 号笔记“分发首选轻量发布、EdgeOne 降为备选”的建议相反，实际默认行为是 EdgeOne，正文 4.3 的写法需要据此复核。
- 生成质量超出提示词要求：自行为“进步分”加了适龄口径说明，教师寄语栏可点开编辑并存在浏览器本地。

## 三点七、补测：Plan模式、Cowriting、定时任务（2026-08-16 23:00–23:25 实做）

### Plan 模式（板块A的骨架，此前只有文档依据，现已坐实）
- **客户端 UI 的标签是“计划 Plan”“仅问答 Ask”**，默认模式无单独名字。文档里的“问一问/做一做/想一想”是另一套说法，写书时以客户端标签为准。入口在输入框“+ → 模式”，是两个开关而非三选一。
- 实际流程比样章原先写的丰富：**先把执行计划写成一份 md 文件** → **弹出结构化澄清问卷**（本次3题：交付物格式／45人分8组除不尽怎么分／6课时排几周，每题可选可跳过）→ 据答案改写计划 → 停在**“开始执行 / 调整计划”两个按钮**前等放行。任务在侧栏标记“待确认”。
- **教师改计划有效且会联动**：我提了两条（第3课时方案设计学生自出、量规第1课时公开），它照改，并自行追加了第6课时互评的呼应修改，最后给出改动前后对照表。
- **验收标准真的被当真**：为塞进“公开量规”5分钟，它把“任务发布”从10分钟压到5分钟，合计仍为40分钟——提示词里“每课时不超过40分钟”起了约束作用。这是“验收标准前置”最好的实证，已写进样章。
- 它自己就把模拟实验排在第2课时。样章原有的“教师纠正实验排第1课时”情节属示例性，不必然发生，已改写为两条真实的教师修改意见。
- 消耗：出计划到待确认共 ◇28.73，未执行。

### Cowriting 划词精修
- 机制：在右侧文档预览区划选文字→浮出“AI 编辑”→评论框输入指令→**划选内容变成一个“文字选区”标记进入主输入框**，指令跟在其后发送。
- **严格只改选区**：把“能积极参与小组活动”改为“每次小组活动均到场，主动承担至少1项分工任务，并在讨论中发言≥2次”，并明确声明同行“良好/待改进”两档未动。右侧预览即时更新，另有“查看所有变更”可回看。
- 极便宜：9秒、◇4.88。样章相应段落已按实测改写。
- 前提：文件要先进入右侧预览区。任务产物点开即可；本地文件仅作为附件挂在提示词上时不会自动进预览区。

### 定时任务（配置全流程走通，未实际创建）
- **“电脑须开机”有了直接依据**：配置页顶部固定提示——“自动化任务执行时，请勿关闭电脑或退出客户端，否则任务将无法正常执行”。此前只能靠推断，现可直接引用。
- 频率支持每天/每周/双周/每月/每年，每周为**星期多选**（默认勾了周一至周四，需手动改为仅周五），时间为滚轮选择器。另有提示“建议避开上午高峰时段，高峰期容易排队等待”。
- 推送渠道两个开关：**推送到 WorkBuddy 微信小程序**、**推送到企业微信 bot**。
- **保存时弹出风险确认（样章原先完全没写）**：“这条自动化任务将以完全访问权限运行……AI 可以直接：写入/修改/删除工作空间内文件；调用已勾选连接器（不再二次提示）；执行 Bash 命令、网络请求等敏感操作”，须勾选“我已了解风险并愿意为执行结果负责”，另有“改为『默认权限』运行”的选项。这一条已写进样章，并据此补了一句教师侧的边界：学生原始记录不该放进无人值守任务的工作空间。
- 出于谨慎未实际创建：在作者电脑上留一条每周五自动执行系统命令的无人值守任务，超出本轮授权范围。表单已填好停在未保存状态，作者若需要可自行确认创建。

## 三点八、定时任务实跑到底（2026-08-16 23:30–2026-08-17 00:10）

建了 `~/Workbuddy/科学护眼周记录/`，从示例数据派生第1–4周记录，第4周人为埋入 G6 整组未交、G3 只交3/6 两处缺漏，再建自动化任务「科学护眼周汇总」（每周五17:00，推送小程序）并点「测试运行」。

### 最重要的一条：项目自动化跑在云端，读不到本地文件
Web 端在项目里建的自动化，执行环境是云端（工作目录形如 `/root/work/…`），**访问不到教师电脑上的目录**。它没有硬编数据，而是停下来问：“您本地的 /Users/…/科学护眼周记录/ 目录我无法访问，上传区和项目网盘里也都没有…如何继续？”并给出三个选项（上传真实周记录／文件已在项目网盘其他位置／先用示例数据出格式演示版）。把四份 CSV 传进项目资产库后，它才读到并跑通。

**因此“教师把周记录放在本机文件夹、让定时任务去读”这条路只适用于客户端的个人自动化**（配置页写明“请勿关闭电脑或退出客户端”，是本地执行）；**项目自动化必须把数据放进项目资产库**。样章板块C 的写法（“存放在本项目资产库中”）是对的，正文无需改；但书中若讲到自动化，应点明这两类自动化的执行位置不同。

其他实测事实：
- 客户端侧栏「自动化」与项目内自动化是**两套独立列表**，互不显示；客户端那套的「运行记录」也不记录项目自动化的执行。
- Web 端「测试运行」按钮**点了没有任何反馈**（无提示、无跳转），但任务确实已在项目「任务」列表中创建并开始执行——我误以为没生效而点了两次，结果起了两个任务。这是个容易踩的交互坑，值得提醒读者。
- Web 端创建自动化**不弹**完全访问权限确认框，客户端创建才弹。同一功能两端的安全提示不一致。
- Web 端「每周」是星期多选（点选切换），客户端也是多选但默认勾了周一至周四；分钟为 5 分钟粒度。

### 输出质量（完整样例见 `书稿/附录/电子资源/周报草稿_实测输出样例.md`）
- 两处埋伏全部命中并单列清单（G6 缺 S31–S35；G3 缺 S16–S18）。
- 数字准确：抽查 G1 本周户外 83.0，与源数据复算一致。它的做法是写 Python 脚本直接从 CSV 计算写入，再“另用 awk 独立复算，逐项一致”——正是验收标准“汇总数字与原始文件逐项对得上”的落实。
- **主动识别幸存者偏差**（提示词未要求）：指出缺席的 G6 恰是上周“连续用眼”最差的组，本周全班均值会“看起来变好”，因此不能直接与上周比较。这是本轮最有教材价值的一处，可作为“AI 也会提醒教师别被数据骗了”的实例。
- **交付前自检**：初稿后自查出“双重括号”“-0.00，下降，基本持平”的矛盾表述，修正复核后才交付。
- 报告开头如约注明“草稿，需教师确认后方可作为项目材料使用”，全文只用小组与学生编号。
